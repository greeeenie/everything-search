# Research v2

MCP для исследования открытого интернета и товарных предложений. Основной движок развёрнут на домашнем Raspberry Pi с 4 ГБ RAM. Российский выход использует домашнего провайдера, европейский — существующий Xray через латвийский VPS.

## Архитектура

На Pi работают MCP, SearXNG, SQLite и worker извлечения содержимого. Worker применяет Crawl4AI к уже загруженному HTML, требующему дополнительного извлечения текста. Страницы с извлечёнными Product/Offer используют полученную разметку. Chromium запускается по необходимости для динамических страниц, по одной странице одновременно.

`EgressRouter` выбирает регион по [config/egress.yaml](config/egress.yaml). Параметр `region` переопределяет выбор для запроса. RU использует прямые соединения отдельного системного пользователя, EU использует локальный SOCKS5 Xray на `127.0.0.1:10808`. Проверка внешнего IP и страны действует перед чтением источников с кэшем состояния на 60 секунд. При ошибке проверки возвращается ошибка соответствующего выхода.

Независимая таблица nftables `research_egress` присваивает трафику пользователя Research существующую bypass-метку sing-box. Правило маршрутизации для этого UID выбирает основную таблицу маршрутов. Установщик сохраняет исходные VPN-файлы, их контрольные суммы, nftables и маршруты в `/var/backups/research-v2/`.

Pi самостоятельно поддерживает SSH-соединение с VPS. Обратный forwarding публикует локальный MCP Pi на `127.0.0.1:8766` VPS. Socket relay на VPS принимает `127.0.0.1:8765` для уже существующего Secure MCP Tunnel. Внешний доступ ChatGPT проходит через авторизацию и HTTPS этого туннеля. Такая схема работает за домашним NAT.

## Инструменты

| Инструмент | Назначение |
|---|---|
| `search_products` | Поиск модели, характеристик и предложений с фильтрами цены и состояния |
| `compare_prices` | Сравнение точной модели с учётом валюты, состояния и вариантов |
| `get_product_details` | Чтение карточки, характеристик и вариантов |
| `get_product_reviews` | Отзывы и обсуждения, связанные с моделью |
| `search_web` | Поиск и чтение открытых страниц с выбором региона |
| `read_page` | Загрузка конкретной страницы и сведения о проверке |
| `research` | Комплексное исследование в режимах `quick` и `deep` |
| `search_hacker_news` | Темы и комментарии HN через публичный Algolia API |
| `search_github_issues` | Issues и выборка комментариев через публичный GitHub API |
| `diagnose_egress` | Фактические IP и страны обоих выходов |

Вызов `research(query, max_threads)` сохраняет прежний формат исследования Reddit через существующий бесплатный индекс Keenable. Комплексный режим включается явно через `mode="quick"` или `mode="deep"`. Новое обнаружение страниц по умолчанию использует собственный SearXNG. Совместимый backend `legacy-index` включается конфигурацией явно.

Быстрый режим ограничен 30 секундами, глубокий — 180 секундами. По завершении бюджета возвращаются собранные компоненты, завершённые веб-страницы и сведения о прерванных проверках. Обобщение выводов выполняет ChatGPT по структурированным данным.

## Достоверность и цены

`Product` описывает модель, `Offer` описывает предложение с ценой, продавцом, состоянием, наличием, доставкой и источником. Адаптеры Ozon, Avito и Яндекс Маркета имеют единый интерфейс. Дополнительные магазины можно передавать доменами в `marketplaces`.

Поддерживаются три статуса доказательств.

- `verified` фиксирует успешное получение содержимого страницы в `checked_at`.
- `indexed_only` обозначает сведения поискового индекса.
- `unavailable` содержит причину недоступности источника.

Каждое предложение содержит собственный URL и evidence с URL прочитанной страницы. Цены извлекаются из публичной разметки schema.org Product/Offer, microdata Avito и видимых карточек выдачи Яндекс Маркета. Наличие, состояние и валюта сохраняются при наличии этих полей. Неизвестные значения остаются явными. Диапазон AggregateOffer используется только как информация о модели и пропускается при извлечении конкретных предложений.

`native_search_marketplaces` включает поиск непосредственно на выбранных площадках. Avito и Яндекс Маркет возвращают предложения из фактически прочитанной выдачи. Ссылки Маркета сохраняют `do-waremd5`, привязывающий переход к предложению. Для Avito при фильтре `condition` дополнительно проверяются отдельные объявления с неизвестным состоянием. `condition_detail_limit` ограничивает число таких проверок четырьмя по умолчанию. Ответ содержит фактическое число проверок и применённый предел.

Точное имя модели, границы чисел и суффиксы помогают отличать Cube 2 Pro от Cube 1 и X5 Pro. Указанные объёмы памяти, цвет и размер учитываются в вариантах. Комплекты и аксессуары фильтруются при поиске отдельной модели. Несовпадающие характеристики источников возвращаются в `specification_conflicts`.

Условия оплаты картой, подписки, купона или кэшбэка помечаются в `price_conditions`. По умолчанию победитель сравнения требует общедоступную цену, подтверждённое наличие, известное состояние и подтверждённую стоимость доставки в заданный город. При недостатке сведений `best_offer` равен `null`, а найденные предложения остаются доступными для анализа.

Параметр `currency` фильтрует предложения по валюте. Для ценового диапазона без явно заданной валюты применяется RUB. При поиске без валютного фильтра предложения сохраняют валюты источников.

SQLite хранит ссылки, нормализованные сведения, фрагменты, время и ошибки. TTL страниц и цен составляет 5 минут, поиска — 3 минуты, ошибок — 2 минуты. `read_page(refresh=true)` запрашивает обновление. История удаляется после 14 дней, очистка запускается ежечасно и при записи данных.

## Автоматические проверки доступа

По разрешению владельца автоматическое выполнение вычислительных проверок включено для источников из `automatic_challenges`. Chromium исполняет проверку сайта и загружает публичную страницу. Подтверждён живой сценарий Avito с `/web/3/firewallPow/`. Для Ozon указаны `/abt/result` и файлы `/s3/abt-challenge/`, однако проверенный домашний выход получил 403.

Конфигурация перечисляет разрешённые домены, CDN, точные пути протокола и каталоги его файлов. POST разрешён только для указанных путей проверки на исходном хосте. Перед чтением содержимого применяются robots.txt и проверка региона. robots.txt разбирается Protego с поддержкой wildcard и приоритетов правил. Состояние анонимных HTTP-cookie разделено по региону и точному хосту.

Отдельный краткоживущий CONNECT-прокси слушает loopback и проверяет публичность DNS перед каждым соединением браузера. Chromium использует собственный HTTPS, а фактический сетевой адрес закреплён прокси. Перехват CDP проверяет URL, методы и каждый переход. Ограничены время, число запросов, переходов и объём трафика. Параллельно работает одна браузерная проверка, извлечение уже полученного HTML имеет отдельный лимит. При тайм-ауте дополнительного извлечения сохраняются успешно полученные исходные сведения.

Поддерживается автоматическое выполнение JavaScript/PoW-проверок сайта. Графические CAPTCHA требуют дополнительного проверенного решателя. Авторизация, 429, неуспешная проверка и региональные ограничения возвращаются явными ошибками. Ошибки и временная пауза источника ограничивают повторные попытки. Платные решатели и прокси в развёртывании отсутствуют.

## Локальная разработка

Требуются Python 3.11+ и uv.

```powershell
uv sync --extra test
uv run pytest -q
uv run ruff check .
uv run python server.py
```

Последняя команда запускает stdio MCP. Для HTTP задайте `RESEARCH_MCP_TOKEN` либо настройте проверенный Secure MCP Tunnel и `RESEARCH_TRUSTED_TUNNEL=1`. HTTP слушает `127.0.0.1:8765`. `/health` предназначен для локальной проверки работоспособности.

## Установка на Raspberry Pi

Требуется 64-битная ОС Linux. Текущий хост использует Debian и Python 3.13. Сначала изучите VPN, IP rules, nftables и локальный SOCKS Xray. Для текущего Pi обнаружены bypass-метка `0x2024` и SOCKS `127.0.0.1:10808`.

```bash
sudo apt-get update
sudo apt-get install -y --no-install-recommends python3-venv git curl nftables chromium
sudo git clone https://github.com/greeeenie/everything-search.git /opt/research-v2
sudo sh /opt/research-v2/deploy/bootstrap-pi.sh
sudo python3 /opt/research-v2/deploy/pi-egress.py install --bypass-mark 0x2024
sudo systemctl start research-egress
sudo python3 /opt/research-v2/deploy/configure-pi.py
```

`bootstrap-pi.sh` устанавливает отдельные Python-окружения Research и SearXNG. `configure-pi.py` создаёт секрет worker непосредственно на хосте и сохраняет его в `/etc/research-v2/research.env` с ограниченными разрешениями. SearXNG получает отдельный секрет. Параметры подключения и секреты передаются сервисам через environment files.

Установщик фиксирует commit SearXNG в `/opt/searxng-research/DEPLOYED_COMMIT`. На уже установленном хосте запускайте bootstrap для изменения зависимостей, затем копируйте новые исходники и перезапускайте соответствующие сервисы. Рабочие настройки находятся в `/etc/research-v2/egress.yaml` и `/etc/research-v2/searxng.yml`.

Основные сервисы доступны через systemd.

```bash
systemctl status research-egress research-v2 research-worker research-discovery research-link
systemctl list-timers research-maintenance.timer
sudo systemctl start research-maintenance.service
journalctl -u research-v2 -u research-worker -n 50
```

Для ручной очистки истории из каталога `/opt/research-v2` выполните следующую команду.

```bash
sudo -u research-v2 env RESEARCH_DATABASE=/var/lib/research-v2/research.sqlite3 /opt/research-v2/.venv/bin/python -m research_v2.maintenance --clear
```

## Связь с VPS и существующим ChatGPT-плагином

Подготовьте отдельный ключ на Pi.

```bash
sudo -u research-v2 ssh-keygen -t ed25519 -N '' -f /var/lib/research-v2/link_key
```

Передайте только `link_key.pub` на VPS и запустите подготовку. Скрипт предполагает уже установленный Secure MCP Tunnel с unit `reddit-research-tunnel.service`.

```bash
sudo python3 deploy/vps-relay.py prepare --public-key /path/to/link_key.pub
```

На Pi передайте публичный host key VPS, полученный через уже проверенное SSH-подключение. Затем запустите настройку с фактическим IP VPS.

```bash
sudo python3 /opt/research-v2/deploy/configure-link.py --vps-ip VPS_IPV4 --host-public-key /path/to/verified-host-key.pub
```

Ключ ограничен удалённым forwarding на `127.0.0.1:8766`. Учётная запись на VPS имеет ограничения SSH и оболочку nologin. Проверка host key включена. systemd восстанавливает соединение при разрыве.

Проверьте `/health` на `127.0.0.1:8766` VPS и активируйте relay.

```bash
sudo python3 deploy/vps-relay.py activate
```

Скрипт сохраняет исходный unit туннеля и меняет его зависимость на socket relay. Для отката выполните `sudo python3 deploy/vps-relay.py rollback`. Исходный сервер VPS и его окружение сохранены для этого отката.

В настройках установленного Research в ChatGPT выполните Refresh, чтобы загрузить новые инструменты и их параметры. Затем можно попросить найти конкретную модель с доставкой в выбранный город или исследовать несколько источников. Примеры запросов находятся в [examples](examples/).

## Docker Compose

[compose.yaml](compose.yaml) предоставляет Research, SearXNG, worker и постоянное хранилище для Linux. На текущем Pi используется systemd. Контейнерный запуск требует проверки образов на целевом Docker-хосте.

Скопируйте `.env.example` в `.env`, укажите фактические UID/GID пользователя с настроенным прямым выходом, создайте секреты и подготовьте каталог данных с этим владельцем. Для VPS задайте `RESEARCH_EU_PROXY` пустым, а `RESEARCH_RU_PROXY` адресом собственного локального SOCKS5 RU-выхода. Проверка стран должна соответствовать выбранной инфраструктуре.

```bash
docker compose --profile worker up -d --build
```

Сервисы используют host networking для доступа к фиксированным loopback-прокси. Research и worker слушают loopback, capabilities сброшены. Worker использует sandbox Chromium и ограничивает параллелизм одной страницей. Для production можно зафиксировать `SEARXNG_IMAGE` по digest. Перед контейнерным запуском остановите соответствующие systemd-сервисы, чтобы освободить локальные порты.

## Проверки и ограничения

Автоматические тесты покрывают SSRF, DNS pinning, сжатые ответы, redirects, robots, кэш, модельные различия, варианты, цены, доставку, TTL ошибок, сохранение частичных результатов, срок истории и MCP-схемы. Живые тесты запускаются на развёрнутом хосте.

```bash
RESEARCH_LIVE=1 /opt/research-v2/.venv/bin/python -m pytest -q -p no:cacheprovider
/opt/research-v2/.venv/bin/python scripts/smoke.py --output /tmp/research-smoke.json
```

Результаты текущего развёртывания и ограничения площадок описаны в [reports/verification.md](reports/verification.md).

Практическая доступность конкретной площадки определяется её robots.txt, правилами доступа и публичной разметкой. Для настроенных источников после проверки доступа предусмотрена одна ограниченная браузерная попытка. Причины окончательной ошибки сохраняются в ответе. Поисковые индексы могут содержать устаревшие и нерелевантные сведения. Отзывы представляют наблюдаемую выборку, а принадлежность авторов к владельцам товара остаётся неподтверждённой.

Официальные API Ozon и Яндекс Маркета описывают интеграции продавцов. Для общего исследования публичных розничных предложений используются доступные страницы. Основания выбора изложены в документации [Ozon Seller API](https://dev.ozon.ru/start/297-Kak-rabotaet-Seller-API-avtorizatsiia-nastroika-i-pervye-shagi/) и [API Яндекс Маркета](https://yandex.ru/dev/market/partner-api/doc/ru/).
